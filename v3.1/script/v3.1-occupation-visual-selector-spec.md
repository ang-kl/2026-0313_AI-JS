# v3.1 Occupation-Sensitive Visual Selector Slice

**Blueprint basis:** `goal/v3-blueprint.md` §8.6 and `goal/v3-ui-blueprint.md` §6.5.

**Accepted UI basis:** the four-item Visuals ribbon in `src/App 2.jsx`.

## Purpose

Add an explainable, reversible selector across the four visual surfaces that are already usable in v3.1:

| Visual | Question | Existing destination |
|---|---|---|
| Graph | What shape is this role? | Preserved Role Graph / FAB workspace |
| Org | What reports up to what? | Organisation Map |
| Workflow | Who acts when? | Workflow Map |
| Value stream | Where does time go? | Value Stream Map |

The selector is navigation first. A recommendation is advisory and never changes the visual automatically.

## Payload contract

The selector reads only an explicit `occupation_visual_profile` (camel-case aliases are accepted) from the result or Work Universe payload. It does not classify a role from its title, duties, employer, SSOC label, or keyword matches.

A recommendation is usable only when all of these are supplied:

1. a supported `primary_visual`;
2. a non-empty `why_this_visual.reason`; and
3. a source identifier on that reason (`source_span`, `source_id`, `evidence_id`, or their camel-case aliases).

The optional ESCO occupation, confidence, work-nature archetype, secondary visuals, and reasons are displayed as supplied. They do not bypass the evidence gate.

## Deterministic visual identifiers

Supported payload aliases normalise to the accepted four destinations:

- `graph`, `role graph`, `concept graph`, `role evidence map` → `graph`
- `org`, `organisation`, `organization`, `organisation map`, `organization map`, `organisation chart`, `organization chart`, `operating model map`, `decision-rights map`, `decision rights map` → `org`
- `workflow`, `workflow map`, `process flow`, `process redesign flow`, `service blueprint` → `workflow`
- `stream`, `value stream`, `value-stream`, `value stream map` → `stream`

All other named grammars remain visible as unavailable. They are not silently remapped to one of the four shipped surfaces.

## Withholding rules

- No profile: show `RECOMMENDATION WITHHELD`; retain all four manual choices.
- Supported primary without a source-linked reason: show `RECOMMENDATION WITHHELD` and identify the missing trace.
- Unsupported primary: show it as `UNAVAILABLE IN THIS BUILD`; retain manual choices.
- Reasons without a source identifier may be shown as unlinked supplied context, but cannot establish a recommendation.
- Selecting a visual is always a user action. The selector never auto-routes.

## Non-regression boundary

This slice does not change Step 1, Step 2, Work Universe geometry calculations, Role Graph/FAB integration, Print/PDF, person-evidence gates, organisation-maturity boundaries, map data contracts, `v3/`, or the Railway root.
