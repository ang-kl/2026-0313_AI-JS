# v3.1 Manual Person-Evidence Ingress

**Blueprint basis:** `goal/v3-blueprint.md` §9.4 and open question 15.6; `goal/v3-ui-blueprint.md` §3.3.

**Accepted UI basis:** the existing `LeapView.jsx` CV-overlay control and textarea. The user selected manual paste.

## Input contract

- The Person lens exposes one manual-paste textarea in the top-left evidence rail.
- Raw text stays in React memory for the mounted Step 3 session.
- No file upload, network submission, browser storage, automatic parser or model extraction is used.
- Pasted text is not a skill, work-history, authority, access or allocation claim.

## Confirmation contract

- Existing target-role skills are shown as manual checkboxes; they are not selected from raw-text matching.
- The user must explicitly confirm ownership and accuracy before evidence becomes active.
- Only checked target skills enter `personEvidence.skills` with `USER-CONFIRMED` status.
- Confirmed raw text becomes one unstructured proof artifact so the evidence is retained without pretending it has been parsed.
- A proof-only confirmation activates the Person evidence anchor but leaves personal skill/delta signals withheld.
- Clearing removes only the in-memory override.

## Output and non-regression

The confirmed evidence is lifted to `ReviewStudio.jsx`, so the same in-memory result reaches the Person projection and the existing Print/PDF resume-alignment rationale. Step 1, Step 2, Organisation Map, Workflow Map, Value Stream Map, Role Graph/FAB, AI Moments, `v3/` and the Railway root remain unchanged.
