# V3.1 Value Stream Map Slice Specification

Status: implementation contract for the blueprint block after the Workflow Map.

## Blueprint question

The Value Stream Map answers: **where does time go, and where does AI actually help?**

It is an organisation-perspective BPR visual for supplied time, waste, queues, waiting, rework, customer delay and delivery friction. Its production silhouette follows the existing `StreamVisual` prototype: ordered stage cards with explicit `value add` or `wait / handoff` labels. It is not a concept graph.

## Scope

This slice adds one dedicated Value Stream Map reachable from the Work Universe Contents tree and Organisation Work Graph detail. It supports only supplied value-stream objects:

- ordered stages, steps or segments;
- explicit value-add, wait, handoff, waste, rework or unclassified state;
- explicit duration, cycle time, wait time and handoff cost labels;
- explicit owner and handoff owner;
- explicit friction and customer impact;
- explicit AI-leverage proposal and do-not-automate boundary;
- explicit current / redesigned scenario and BPR hypothesis labels;
- explicit governance references and human-validation requirements.

It does not derive timing, waste, process quality, savings, layoffs, automation potential or organisation maturity from posting duties, stage count, role title, ESCO family, Workflow Map or Organisation Map.

## Accepted payload paths

The deterministic adapter reads the first non-empty value-stream object from:

1. `result.workUniverse.valueStreamMap`
2. `result.workUniverse.value_stream_map`
3. `result.workUniverse.valueStream`
4. `result.workUniverse.value_stream`
5. the equivalent paths under `result.work_universe`
6. `result.valueStreamMap`
7. `result.value_stream_map`

Within that object:

- stages: `stages`, `steps`, or `segments`;
- explicit map summary: `summary`, `totals`, or `metrics`;
- source links: `evidenceIds`, `evidence_ids`, `sourceIds`, `source_ids`, `spanIds`, `span_ids`, `src`, or `sources`.

Aliases are normalised only; the adapter adds no semantic claims.

## Evidence and withholding rules

- A stage is usable only when it has an explicit label.
- Array order is respected only inside an explicitly named stage collection. Explicit numeric `order`, `sequence` or `position` takes precedence.
- Classification is read only from a supplied classification/type field. Stage text is not classified by keyword.
- Durations and costs remain display labels. The adapter does not sum mixed values or invent units.
- AI-leverage text remains a proposal. A supplied agent candidate without both human owner and governance reference is visibly blocked rather than promoted.
- Missing source-span links show `No source-span link supplied`.
- Missing value-stream payload shows a dedicated `WITHHELD` state and explains why.
- BPR content is labelled as hypothesis unless the payload explicitly labels another evidence state.
- No savings, layoffs or process-quality conclusion is produced.

## Interaction and accessibility

- Every supplied stage is a keyboard-reachable button with a minimum 44px target.
- Selecting a stage opens its supplied detail, provenance and source ids.
- Matching source ids route to the existing evidence selection path.
- The map owns vertical and horizontal overflow.
- Desktop keeps the three-panel workbench; tablet and mobile use the existing dedicated-map viewport treatment.
- State uses text and border treatment, never colour alone.
- Reduced-motion preferences disable transitions.

## Acceptance

- Empty contract test proves no timing, waste or AI leverage is fabricated.
- Supplied contract test proves deterministic ordering and preservation of explicit classifications, timing labels, owners, boundaries and source ids.
- Ungoverned supplied agent candidates are blocked.
- Chromium gate opens the Value Stream Map from the tree, verifies the withheld production fixture, returns without losing state, and checks desktop/tablet/mobile scroll reachability.
- Production build passes.
- Blueprint cross-reference changes to `BUILT` only after these gates pass.
