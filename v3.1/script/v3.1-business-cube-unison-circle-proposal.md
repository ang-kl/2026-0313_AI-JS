# v3.1 Business Cube - unison circle renderer

**Status: PROPOSAL. Not approved, not scheduled, no code written.**
Proposes an additional renderer over the existing Business Cube model. Amends nothing
in `v3.1-business-rubiks-cube-spec.md` until the Human Lead rules on section 7.

## 1. The problem, measured

`businessCubeModel.js:85-118` builds exactly 27 cells: 3 functions x 3 work layers x
3 allocations, each carrying `count`, `status` (`evidenced` or `withheld`), its
clusters and its agents. Every one of the 27 is a real datum. `BusinessRubiksCube.jsx`
renders all 27 as meshes.

A solid 3 x 3 x 3 cannot show 27 cells at once. Index the cells `x, y, z` in `{0,1,2}`
and view the three faces `x=2`, `y=2`, `z=2`. A cell is visible only if it has a face
on one of them. The cells with `x<2` and `y<2` and `z<2` number `2 x 2 x 2 = 8`.

- **8 of 27 cells, 30%, are hidden from any single viewpoint.**
- **The centre cell `(1,1,1)` has no outer face at all, so it is never visible in any
  unexploded 3D view, from any angle, at any zoom.**

Rotating trades one hidden set for another; it does not reduce the count. The existing
`explode` control (`BusinessRubiksCube.jsx:19,33,35`) is an acknowledgement of this
rather than a remedy, since an exploded view still occludes and adds depth ambiguity.

The evidence contract makes this worse than a display inconvenience. The spec requires
that *"empty cells remain visible as withheld cells. They are not evidence of absence."*
A withheld cell that is also geometrically hidden is withheld twice, and the second
withholding is silent. The diagram cannot keep a promise the geometry breaks.

## 2. Proposal

A second renderer, polar rather than cubic, over the **same** `buildBusinessCubeModel`
output. No change to the model, the evidence rules, or any upstream stage.

```
hub        sector evidence: exact ACRA primary SSIC description and code,
           or "Sector evidence withheld"   (unchanged from the existing spec)

rings      work layer, inner to outer:  Govern -> Coordinate -> Execute
sectors    function, three arcs of 120 degrees
slots      allocation, each function arc divided into three arcs of 40 degrees:
           Human-held, Augmentation review, Agent candidate

           3 rings x 9 angular slots = 27 tiles, all visible simultaneously
```

Governance sits innermost because a radial layout reads its centre as the core, and
because Execute is where the work surface is. Function is the primary angular division
because function is the axis that carries withheld slots (`withheldFunction`), so a
wholly unevidenced function reads instantly as one empty third of the ring.

## 3. What this preserves

- All 27 cells visible at once, including the cell 3D can never show.
- Withheld cells remain visible as withheld, which is the contract the cube cannot keep.
- The centre sector rule is unchanged, including `Sector evidence withheld`.
- Duty extraction, clustering, recurrence, exposure, promotion, SAT and provenance are
  untouched. This is a renderer.
- Still an organisation work-allocation lens, not an organisation chart, value stream,
  process model, workforce forecast or deployment recommendation.

## 4. What this loses, stated rather than discovered later

**True three-axis adjacency.** In the cube each cell has up to six orthogonal
neighbours and "next to" means something on all three axes. In the polar layout only
two adjacencies are real: radial, which is work layer, and angular within a function
arc, which is allocation. **Angular adjacency ACROSS a function boundary is an
artefact of the layout and means nothing.** Mitigation is mandatory rather than
cosmetic: an explicit gap and rule between function arcs, so no reader can mistake the
seam for a relationship.

**The cube metaphor.** If "Business Rubik's Cube" carries naming or narrative value,
the circle does not inherit it. Section 7 asks whether both should exist.

## 5. Why polar rather than the alternatives

| Option | All 27 visible | Keeps cell identity | Cost |
|---|---|---|---|
| Rotate or explode the cube | No | Yes | 8 hidden at any angle; centre never visible |
| Three 3 x 3 slices, small multiples | Yes | Yes | Reader reassembles the third axis mentally; no unison |
| Flat 9 x 3 matrix | Yes | Yes | Honest and dull; loses the centre as sector identity |
| **Polar, this proposal** | **Yes** | **Yes** | Cross-function angular adjacency is meaningless and must be marked |

The flat matrix is the honest baseline and the spec already names one as the
non-3D fallback. The polar layout earns its extra complexity only by keeping the hub
meaningful, which is where the sector evidence already belongs.

## 6. Accessibility and honesty, which gate this on implementation

CLAUDE.md section 4 fires on implementation because this is a user-facing result
surface. `conformance-auditor` and `a11y-honesty-reviewer` run before any merge.

- Colour is never the sole signal. `withheld` is carried by hatch and by text, not hue.
- The innermost ring has the smallest tiles. Either the inner radius is set so the
  smallest tile meets a 44px touch target, or selection is guaranteed through the
  accompanying list. Not both left to chance.
- Each tile carries an aria label naming function, work layer, allocation, count and
  status.
- The footer keeps `AI-assisted; human decides` and the Source / Confidence /
  Time-window line.
- One a11y gain over the cube: no orbit, pan or zoom, so no 3D keyboard model. Tab
  order through 27 tiles is linear and predictable.
- Non-ASCII characters stay out of JSX string literals per rule R007.

## 7. Decisions for the Human Lead

1. **Replace the cube, or add the circle beside it as a toggle?** Recommended: add
   beside. The cube makes the point that you cannot see every consequence at once, and
   the circle answers it. Keeping both makes the non-regression boundary trivial and
   costs one control.
2. **Ring order.** Govern innermost as proposed, or Execute innermost.
3. **How `count` is encoded.** Tile fill density, a printed number, or both.
4. **The name.** "Unison circle" is the Human Lead's term from the brief and is used
   throughout this document; the product may want something in its own vocabulary.
5. **Version bump.** A new renderer is `new_feature_added` under `bump_decision`, which
   is a minor bump requiring Human Lead confirmation under Rule V-1. Surfaced per Rule
   V-2, not assumed.

## 8. Not in scope

Not proposed here, and not to be folded in quietly: any change to the evidence model,
the three axes, the sector rule, Step 2 behaviour, `v3/`, Railway configuration, the
Workflow Map, the Value Stream Map, the Organisation Map evidence rules, or the AI
Moments analysis model.
