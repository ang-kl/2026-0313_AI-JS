# V3.1 Workflow Map Slice Specification

Status: implementation contract for the next blueprint block after the Organisation Map.

## Blueprint question

The Workflow Map answers: **who acts when, and in what sequence?**

It is a process-flow visual, not a concept graph and not an organisation-maturity assessment. Its production silhouette follows the existing numbered `WorkflowVisual` prototype while adopting the current v3.1 Work Universe visual language.

## Scope

This slice adds one dedicated Workflow Map reachable from the Work Universe Contents tree and the Organisation Work Graph detail. It supports only supplied workflow objects:

- ordered stages or steps;
- explicit actors, lanes, owners and human owners;
- explicit decisions;
- explicit handoffs, dependencies and transitions;
- explicit queues and bottlenecks;
- explicit current/redesigned labels, agent candidates and friction labels.

It does not derive process order from the job-posting duty array, keywords, role title, ESCO family or Organisation Map. Occupation-sensitive visual selection and value-stream timing remain separate blueprint blocks.

## Accepted payload paths

The deterministic adapter reads the first non-empty workflow object from:

1. `result.workUniverse.workflowMap`
2. `result.workUniverse.workflow_map`
3. `result.workUniverse.workflow`
4. `result.work_universe.workflowMap`
5. `result.work_universe.workflow_map`
6. `result.work_universe.workflow`
7. `result.workflowMap`
8. `result.workflow_map`

Within that object:

- nodes: `steps` or `stages`;
- edges: `transitions`, `handoffs`, `dependencies`, or `edges`;
- source links: `evidenceIds`, `evidence_ids`, `sourceIds`, `source_ids`, `spanIds`, `span_ids`, `src`, or `sources`.

Aliases are normalised only; the adapter does not add semantic content.

## Evidence and withholding rules

- A node is usable only when it has an explicit label.
- A relationship is usable only when both endpoints resolve to supplied nodes by id or exact label.
- Array order is respected only inside an explicitly named `steps` or `stages` collection. Explicit numeric `order`, `sequence` or `position` takes precedence.
- No edges are created between adjacent array entries.
- No actor, owner, decision, queue, friction, bottleneck, automation candidate or redesigned state is inferred.
- Missing source-span links show `No source-span link supplied`.
- Missing workflow payload shows a dedicated `WITHHELD` state and explains why.
- Invalid/unresolved explicit relationship rows are counted and disclosed; they are not silently drawn.
- Job-posting sequence is not treated as organisation maturity, process quality, staffing condition or workflow truth.

## Interaction and accessibility

- Every supplied stage is a keyboard-reachable button with a minimum 44px target.
- Selecting a stage opens its supplied detail and provenance.
- Source ids route to the existing evidence selection path.
- The main flow owns vertical and horizontal overflow.
- Desktop, tablet and mobile retain readable labels without requiring hover.
- Status never relies on colour alone; `SUPPLIED`, `WITHHELD`, `DECISION`, `QUEUE`, `BOTTLENECK`, and scenario labels remain textual.
- Reduced-motion preferences disable transitions.

## Acceptance

- Empty contract test proves no sequence is fabricated.
- Supplied contract test proves deterministic ordering, explicit relationships, decisions, actors, handoffs and source ids.
- Chromium gate opens the Workflow Map from the tree, verifies the withheld production fixture, returns to the universe without losing state, and checks desktop/tablet/mobile scroll reachability.
- Production build passes.
- Blueprint cross-reference changes to `BUILT` only after these gates pass.
